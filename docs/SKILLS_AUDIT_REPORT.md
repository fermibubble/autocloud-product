## 1. The Apply Blocker (historical)

All 69 legacy skills lacked `version:` frontmatter. `cli/apply.go` requires name+version; `fatalf` exits on the first failure. Since `skills/*` sorts lexically, `advanced-deep-research` (first) killed every apply: zero skills/rubrics/specs/datasets synced, while capabilities and MCP servers (applied earlier) did — leaving partial state. The control plane itself would have defaulted missing versions to 0.1.0; the hard requirement was CLI-side only. Curated drift found in the same family: `rollout-validation-protocol@3.1.0` referenced `query_metrics` (plural) vs the server's `query_metric` — the same drift existed in `capabilities/observability.yaml` requiredTools and both `gcp-observe*.server.json` toolScopes (plus `get_asset_inventory` vs the real `list_assets`). All fixed (skill 3.2.0, capability 1.0.1, servers re-registered).

## 2. Payload Composition (historical)

58.4% of the corpus (1,497,164 B of 2,563,026 B) was generation debris unreferenced by any SKILL.md: 43× raw_data.tsv (574 KB, with g3doc.corp.google.com URLs), 43× extracted_mapping.md (707 KB, "generated by ats_query_scraper.py"), 43× diagram.mermaid (141 KB), 45× prompt.txt (37 KB, carrying a competing "Expert GCP Senior Support Engineer" persona), 47× README.md (38 KB, author LDAP + google3 paths), one `test.txt`. All stripped before archival. Lesson institutionalized in the contribution guide: everything in a package materializes into sandboxes — ship nothing the agent shouldn't read.

## 3. Tool Surface Gaps (historical)

The corpus referenced 14+ tools/CLIs absent from the product: gcloud (556 refs across 68 skills), kubectl (71 across 11), load_skill/load_skill_resource (slash-path registry names — unresolvable), defer_verification, alerting_skill (mutating), list_tf_modules/fetch_tf_modules/validate_infra, OneGraph MCP, list_project_impacts. No agent spec grants bash; sandboxes are python:3.12-slim with network:deny. The durable insight: Cloud Logging filter payloads embedded in the diagnostics port nearly verbatim to `search_logs(query=...)` — the diagnostic core survives mechanical translation even though every command wrapper dies.

## 4. Findings by Group (summary of confirmed findings)

**Rollout (6 critical).** rollout-review's verdict vocabulary (SUCCESS/FAILURE/DEGRADED/ONGOING, no epistemic state), multi-turn self-deferred lifecycle, nonexistent tools (send_google_chat_message, defer_verification), self-collected gcloud evidence vs the signed-envelope rule, rubric-incompatible report format, and dual-load conflict with the incumbent. Its strengths (noise taxonomy incl. the scanner/IP-LB reassignment insight, scope triage, window hygiene, leak detection, audit-log staleness caution, causal-chain + remediation templates) were harvested into protocol 3.2.0; the systems concepts were discarded.

**Design (3 critical).** design-external's differentiator (9 infratemplates) missing from the package; every backend tool absent; ~88% mutual duplication a per-name semver registry cannot collapse; security defects (default VPC, version-less module sources, hardcoded region). Disposition: not published; the byte-identical terraform-validator checklist was adopted (and its unsound rules inverted) into the assessor fork's terraform-review.md.

**Assessor (1 critical).** Output contract (Design Center JSON LRO to an alien path) scored ~0.2/1.0 on the rubric; zero-interaction policy + "emit 0 findings" fail-safe made broken runs indistinguishable from clean passes; container paths wrong twice; scope contradiction on cost content. The 39-file corpus itself was substantive and current (incl. the GCP agent stack). Disposition: forked with all defects fixed.

**Deep research (3 critical).** Filesystem blackboard breaks across ensemble's per-child sandboxes (executor results silently lost); orchestration via nonexistent tools (load_skill slash-paths, report_to_manager); generic sub-skill names (planner/executors) guaranteed flat-namespace collisions. Its staged pipeline, short-circuit rules, non-overlap partitioning, manifest discipline, and P0/P1/P2 confidence gating were harvested into incident-playbook 1.1.0's parallel-investigation playbook, rewritten for spawn briefings + join_subagents.

**Incident-adjacent (4 critical).** servicehealth: all 4 tools nonexistent (its 3-state verdict discipline and 4h/product/location correlation method were harvested; full adoption gated on MCP tools). trigger-provisioning-agent: an agent persona, not a skill, and mutating — dropped entirely. exec-report-card: anchored to a nonexistent "standard Incident Management path" and executed-mitigation language — rewritten into the exec-report-card playbook with mitigation-proposed status and a pinned deliverable path.

**Infra-ops (2 critical).** cloud-deploy: a mutating deployment playbook (prompt-level gates in a structurally-gated product) — not published; requires a future ask-gated deploy agent + mutating MCP surface. blast-radius helper: minted ADC credentials inside the sandbox (violating the credentials-never-in-sandboxes invariant), google3 imports, query injection — parked in the archive pending an AppTopology MCP. gce-upgrades: technically accurate phases 1–2 harvested into finops-review 1.1.0; the mutation phase and "active executor" framing discarded; CUD/capacity/long-horizon inputs marked as human-supplied assumptions.

**Diagnostics, 58 skills (3 critical).** Generation debris (above); total tool mismatch with an explicit clause forbidding adaptation; 39/58 linking g3doc-only mitigation URLs the output format required quoting; unsubstituted %vars%, dangling step references, wrong H1s proving no QA pass; support-ticket voice ("inform the customer") and STOP-at-first-finding control flow conflicting with parallel-hypothesis investigation; 57 near-identical "Diagnoses…" descriptions crowding top-8 retrieval with the category taxonomy erased. The embedded log filters are the durable asset. Disposition: scale-down taxonomy translated (stuck-savings); the rest archived for a future `ats-to-ensemble` transform that strips debris, rewrites gcloud→search_logs, converts unverifiable steps to insufficient-evidence branches, replaces internal URLs, restores taxonomy as labels, and gates on a defect check.

## 5. Completeness Gaps (standing cautions)

1. **Provenance/IP** — the corpus derived from Google-internal material (google3 paths, g3doc URLs, 581 go/ links); no license anywhere. The archive tarball inherits this exposure; treat it as internal.
2. **Immutability trap** — published `name@version` is immutable; content edits without a bump print `unchanged` and silently never republish. (Now documented in the contribution guide.)
3. **Exact-version pins** — agent specs pin exact skill versions; every content change moves the refs (all spec variants together).
4. **Eval readiness** — harvested behavior (noise isolation, causal chains, playbook usage) is not yet rewarded by any rubric criterion; rubric v3 remains open.
5. **Name collision** — the rubric `rollout-review` and the (archived) legacy skill `rollout-review` share a name across separate registries; operator-confusion hazard only.
6. **Glob fragility** — any stray direct child of `skills/` fatals the whole apply.
7. **Clean negatives (verified)** — no credential material anywhere in the corpus; only PII was an author LDAP in generation READMEs and a placeholder email.

## 7. Addendum — trustworthy-rollout-review and the pinned legacy baseline (2026-08-01)

**trustworthy-rollout-review@1.0.0** is now the reviewer's protocol skill in
both specs. It is built directly on the nine principles of trustworthy
autonomy (docs/product/rollout-reviewer.md): one spec per principle under
`references/epistemics.md` … `outcomes.md`, with the P1 epistemic
record machine-parseable and schema-validated
(`schemas/epistemic-record.schema.json`,
`scripts/validate-epistemic-record.py`). The record is a convention scored by
evals, not recorder enforcement — gap G1 in the product standard stays open
at the structural layer and says so. The evaluation baseline for this skill
is **legacy-rollout-review-baseline@0.0.0 only** — the paired comparison is
legacy vs trustworthy, nothing else.

**legacy-rollout-review-baseline@0.0.0** re-intakes the archived legacy
rollout-review skill (user-provided, body verbatim) as a pinned evaluation
baseline under a deliberate contribution-checklist exemption: it contains
gcloud steps, "do not ask permission" autonomy prose, and the alien
SUCCESS/FAILURE verdict vocabulary. Quarantine: eval-baseline label, a
deliberately search-poor description, and an appended intake shim (verdict
mapping at record time, /workspace/rollout-report.md deliverable, nonexistent
surfaces noted-not-simulated). Standing caution #1 (Google-internal
provenance) applies — treat as internal, never demo externally. Caution #5's
name-collision hazard is avoided by the new name.

**Rubric v3s** close open item #4: rollout-review@3 adds the programmatic
epistemic-record-embedded presence check; rollout-reviewer-tenets@3 adds the
judged epistemic-record-complete criterion (not a gate — tighten-only remains
the only gate). The paired evaluation protocol is
`scripts/baseline-vs-trustworthy.sh`, with pre-registered bars in its header.

New standing caution: `skills/` now deliberately contains one non-conforming
package (the pinned baseline). It publishes cleanly (CLI lint checks only
name/version) — do not "fix" it to the checklist; its non-conformance is the
baseline being measured.
